# Gün 18 - Engel Kayıtları

## Sorun

Ubuntu sanal makinesinde Splunk Enterprise kurulumunun tamamlanmasının ardından web tarayıcısı üzerinden yönetim arayüzüne (`http://localhost:8000`) erişilmeye çalışıldı.

Ancak web arayüzüne ulaşılamadı ve Firefox üzerinde *"Firefox localhost:8000 sunucusuna bağlanamadı"* uyarısı alındı. Servis arka planda çalışmıyordu ve doğrudan servis yeniden başlatılmak istendiğinde Splunk'ın güvenlik politikası süreci durdurdu.

## Hata Mesajı

Tarayıcıda bağlantı hatası alındıktan sonra terminal üzerinde servis durumu sorgulandığında ve yeniden başlatma komutu verildiğinde şu tam hata ve uyarı mesajları ile karşılaşıldı:

> "splunkd is not running."

> "Running Splunk Enterprise as root is deprecated and will be removed in a future release. For details, see the Release Notes. To run as root, use the --run-as-root option."

## Denenenler

### 1. Servis Durumunun Terminalden Kontrol Edilmesi

Arka planda sürecin aktif olup olmadığını görmek için Splunk CLI üzerinden durum sorgulandı:
```bash
sudo /opt/splunk/bin/splunk status
```
**Sonuç:** `splunkd is not running.` yanıtı alındı; arama ve web motorunun aktif olmadığı görüldü.

### 2. Standart `restart` Komutuyla Başlatma Denemesi

Çöken veya başlamayan servisi ayağa kaldırmak amacıyla sudo yetkisiyle doğrudan yeniden başlatma komutu çalıştırıldı:
```bash
sudo /opt/splunk/bin/splunk restart
```
**Sonuç:** Splunk 10.x sürümünün güvenlik mekanizması devreye girdi. `root` kullanıcısı ile doğrudan başlatma davranışı reddedildi ve komut yürütülmeden sonlandırıldı.

### 3. Port Dinleme Durumunun Denetlenmesi

8000 web portunun herhangi bir süreç tarafından dinlenip dinlenmediği kontrol edildi:
```bash
sudo ss -tulpn | grep 8000
```
**Sonuç:** Çıktı boş döndü; Splunk web servisinin (splunkweb/CherryPy) dinleme moduna geçmediği teyit edildi.

## Çözüm

Sorunun, Splunk 10.x sürümünde gelen sıkılaştırılmış kullanıcı yetkilendirme politikasından kaynaklandığı anlaşıldı. Splunk, güvenlik açığı riskini azaltmak amacıyla root oturumu altında doğrudan çalışmayı varsayılan olarak engellemektedir. Lab ortamında root haklarıyla devam edebilmek için bu güvenlik denetimini bilinçli olarak aşan özel çalıştırma bayrağının verilmesi gerektiği tespit edildi.

## Nasıl Çözüldü?

1. **Zorunlu Root Parametresinin Kullanılması:** Terminalde başlatma komutuna `--run-as-root` argümanı eklenerek servis tetiklendi:
   ```bash
   sudo /opt/splunk/bin/splunk start --run-as-root
   ```
2. **Süreç ve Port Doğrulaması:** Splunk daemon'u (`splunkd`) ve web arayüzü motoru başarıyla ayağa kalktı. Terminal çıktısında web arayüzünün hazır olduğu bilgisi (`The Splunk web interface is at http://...:8000`) görüldü.
3. **Arayüz Erişim Testi:** Firefox tarayıcısında sayfa yenilenerek `http://localhost:8000` adresine gidildi; Splunk Enterprise giriş ekranı açıldı ve `vboxuser` bilgileri ile panele başarıyla oturum açıldı.

## Sonuç

Bu çalışma sonucunda, kurumsal güvenlik yazılımlarının (özellikle Splunk Enterprise gibi servislerin) varsayılan olarak root yetkileriyle çalışmaktan kaçındığı ve en az yetki prensibini (Principle of Least Privilege) dayattığı görüldü.

Lab ortamlarında hızlı doğrulama için `--run-as-root` bayrağının kullanımı öğrenilirken, üretim (production) ortamlarında servisi çalıştırmak için neden özel bir sistem kullanıcısının (`splunk`) tanımlanması gerektiğinin mantığı pekiştirildi.
