# Gün 15 - Engel Kayıtları

## Sorun

Windows tarafında Sysmon (System Monitor) logları üzerinden süreç oluşturma kayıtları incelenerek `notepad.exe` gibi spesifik bir sürecin tetiklenme anı ve üst süreç (`ParentImage`) ilişkisi tespit edilmeye çalışıldı.

Ancak Sysmon, arka planda son derece yüksek hacimde sistem aktivitesi logladığı için Event Viewer (Olay Görüntüleyicisi) içerisinde binlerce Event ID 1 (Process Create) kaydı üretildi. Bu durum, aranan spesifik programın manuel olarak taranmasını ve bulunmasını zorlaştırdı.

## Hata Mesajı

Doğrudan bir sistem hata kodu alınmadı; ancak Event Viewer arayüzünde manuel metin araması (Find) yapılırken şu uyarı mesajı ile karşılaşıldı:

> "Searching from the selected event to the end of the list, there is no event that contains the specified string. To search all events, select the first event in the list and run the search again."

## Denenenler

### 1. "Filter Current Log" (Mevcut Günlüğü Filtrele) Arayüzü Üzerinden Metin Araması

Arayüzdeki filtreleme penceresi kullanılarak doğrudan `notepad.exe` araması yapılmaya çalışıldı.

**Sonuç:** Arayüzdeki bu pencerede sadece sayısal Event ID (örn. `1`) filtrelemelerine izin verildiği, metin tabanlı serbest arama kutusunun bulunmadığı fark edildi.

### 2. Event Viewer "Find" (Bul) Aracıyla Eksik Yönlü Arama

Listede rastgele bir satır seçiliyken sağ menüden `Find...` seçeneği kullanılarak `notepad.exe` aratıldı.

**Sonuç:** Arama imlecinin bulunduğu noktadan listenin sonuna kadar tarama yapıldığı için aranan metne ulaşılamadı ve yukarıdaki uyarı penceresi alındı.

## Çözüm

Sorunun Sysmon'un yüksek gürültü/log hacminden ve Event Viewer arayüzünün varsayılan arama davranışından kaynaklandığı anlaşıldı. Sysmon loglarında spesifik bir süreci yakalayabilmek için doğru filtreleme veya arama yönünün seçilmesi gerektiği tespit edildi.

## Nasıl Çözüldü?

1. **Arama İmlecinin Taşınması:** Uyarı penceresi kapatıldıktan sonra Event Viewer listesindeki **en üstteki ilk log kaydına** tıklanarak seçim en başa taşındı.
2. **Yeniden Arama:** Sağ menüden `Find...` aracı tekrar tetiklenerek tüm log yığını baştan sona taratıldı ve `notepad.exe` sürecine ait Event ID 1 kaydı başarıyla yakalandı.
3. **Alternatif Yöntem (PowerShell):** Event Viewer arayüzünün yavaş kalabileceği durumlarda, `Get-WinEvent` komutuyla PowerShell üzerinden filtreleme yapılabileceği teyit edildi.

## Sonuç

Bu çalışma sonucunda, Sysmon gibi görünürlük araçlarının çok yüksek miktarda log ürettiği (`log noise`), bu nedenle ham liste üzerinde manuel arama yapmanın verimsiz olduğu görüldü. 

SOC analistliği pratiğinde, Event Viewer filtreleme mantığının, `Find` aracını kullanırken imleç konumunun (`first event`) ve PowerShell sorgularının önem bir kez daha teyit edildi.
